# 做菜线（cookline）

先读[插件 README](../../../08_作品/_共享工具/cookline/README.md)的「四、菜谱卡」「五、五条命令」「六、30 条拦截」。开始新菜时先用[做菜短片规划卡](../../../05_模板/做菜短片规划卡.md)，由菜品工艺与本集情境推导段落，再为每段规划提示词、道具状态、分镜和声音；不预设段数、工序顺序或结尾。做可爱角色的生活化做饭片时，可把[秃秃青菜包逐拍拆解](../../../08_作品/心易做菜/00_方案/06-青菜包逐拍拆解与声音庆祝设计-20261104.md)和[秃秃原片拉片](../../../08_作品/小蛋仔做菜/00_方案/01-参考拉片-蘑菇做饭日常.md)当作样本库，不复用成统一步骤表。青菜包原片动作声音本轮未听辨，拟音仍是候选设计。使用心易时，同时读[心易·跨项目角色规范](../../../08_作品/_共享角色/心易/README.md)；其无台词设定适用于所有题材。读[翻车登记表](../../../08_作品/_共享工具/cookline/rules/failures.json)定位具体编号；需要格式依据时读[16 拍设计](../../../08_作品/心易做菜/00_方案/04-参考工作流设计挖掘-v1.md)和[秃秃日常补充观察](../../../08_作品/心易做菜/00_方案/05-秃秃做饭日常补充观察-20261104.md)。需要补故事动机、角色连续性或节拍拆分时，可用[I09](../../../03_行业Skill/I09-故事转手绘动画.md)；需要逐段分镜/提示词检查时读[I10](../../../03_行业Skill/I10-逐场分镜与连续性.md)；需要“先做菜品动作板再进视频”的参考时读[I11](../../../03_行业Skill/I11-烹饪动作参考板.md)。三者只取对应方法，不搬用外部画风、固定九步/网格、专属平台工具或角色台词。

## 什么时候用

- 要做一条新的做菜短片：先定菜、定角色、定台地，再写菜谱卡。
- 已有菜谱卡要出画布：校验 → build → 过闸门。
- 出片后返修：先用 `doctor` 看是不是手改，再改卡重建。
- 旧卡（小蛋仔 `build_from_recipe` 或心易 `build_from_slope`）：先 `migrate` 做兼容审计，不直接 build。

## 流程

1. **先做菜品与故事规划**：按菜的工艺列出必要状态转换、视觉变化和可省略步骤，再结合角色处境组织本集段落。段数、顺序、节奏、场景切换与结尾按菜决定，不套统一菜谱戏剧。参考[做菜短片规划卡](../../../05_模板/做菜短片规划卡.md)。
2. **逐段展开制作包**：每段同步确定时长依据、动作起止、角色/道具/食材/场景状态、分镜帧和视频提示词；分镜帧数随动作复杂度与模型能力决定。声音、拟音、停顿、庆祝、试吃和分享按需要选用。可借[I10](../../../03_行业Skill/I10-逐场分镜与连续性.md)的逐段提示词/连续性检查，以及[I11](../../../03_行业Skill/I11-烹饪动作参考板.md)先做可审动作板的顺序；不套固定九步、段数、网格或风格。
3. **映射到菜谱卡**：先看当前编译器支持什么，再把规划映射为卡；每拍写 `start/do/end`，填 `props/hand/counts/state` 账本。为本集显式写 `format.tone`。道具后面要用，首拍就得在画面里，或由 `enter` 带进来。
4. **校验**：`run.py check <卡> --strict`；ERROR 必须清零，WARN 要么改卡要么记录原因。段数、每段整秒时长、动作拍数和 `storyboard_frames` 数量均可变；旧卡仍用全局秒数/三格配置兼容。新卡必须为每段明确分镜帧数/时间点；自动推导只用于草稿预览。每段至少有一个动作，并确保动作时间轴覆盖该段；非分享结尾需在末段填写 `ending_intent`。目标模型是否支持所填时长，生成前按当前工具能力核实。
5. **出画布**：`run.py build <卡> -o <x.monet>`；同时得到 runlist、边车、SRT。**不导入、不派发。**
6. **过闸门**：`assets → storyboard → keys → videos`，每道 `gate approve` 必须写看到了什么；`runlist` 只放行，用户明确说「跑」才派发。
7. **出片后**：`doctor` 查画布；按 F01–F29 逐条过，新翻车补进 `rules/failures.json` 并加一条反例测试。

## 按菜设计，不套统一菜谱戏剧

先问这道菜的视觉/动作核心是什么，再决定它需要怎样的故事和表演：

- 青菜包可突出揉面回弹、收褶成形、蒸汽揭晓；可以慢，也可只留下最有触感的几步。
- 炒菜可突出食材下锅的瞬间、锅气、翻炒节奏和颜色变化；节拍可以更短、更有脉冲。
- 汤羹可突出切配、慢煨、汤面变化和舀起后的热气；等待可以承载情绪，不必额外制造忙碌动作。
- 糯米团/甜点可突出裹馅、滚圆、表面沾粉或切开后的截面；落点可以是试吃、摆盘、带走或留给明天。

这些是设计提问示例，不是固定菜式模板。每集选一个主动作/材质作为记忆点，辅以必要的角色反应；动作声音只在能增强触感或节奏时安排，完成反馈只在结果值得角色回应时安排。连续性、手部、道具、食材状态和心易人设仍是硬约束；段落顺序、快慢、生活动机和结尾方式按这道菜来定。

## 动作表演与声音（可选设计工具）

- 只挑本集一两个最有表现力的动作设计拟音；其他动作可留环境声、音乐或安静。声音按食材与工具材质匹配，不为填满拍点而添加。
- 如果某个结果值得庆祝，再给角色一个可见反馈：停下来端详、点头、托起成果、轻弹一下或分享。没有情绪需要时就顺着动作继续；不要求每段庆祝或每集分享。
- 使用心易时，食材和工具拟音与角色发声分开记；心易只用全局规范许可的“咔啵”语气变化，不用新的拟声词代替台词。表演须满足固定玩偶眼睛、短圆手无手指等约束。
- 参考观察见[青菜包逐拍拆解](../../../08_作品/心易做菜/00_方案/06-青菜包逐拍拆解与声音庆祝设计-20261104.md)。该片动作声音未听辨；关于拟音与阶段反馈的内容是本项目候选设计，尚未出片验证。
## 硬规矩

- **卡是唯一内容源**：提示词、字幕、节点都从卡生成；不手改 `.monet`，改了会被 digest 抓住。
- **字幕只进 SRT**：提示词里只写「不生成任何字幕」，不写具体文案。
- **一段一个台地**：要换景就拆两条；段间只带得走的东西，用 `carry` 声明。
- **旧卡不硬跑**：`migrate` 只做审计；补不齐 `props/hand/state` 就不 build。
- **校验通过 ≠ 好看**：表演、节奏、治愈感留给人，不写成通过。
- **不越权**：不生成、不导入、不删除、不发布；付费与派发每次都要用户明确授权。
