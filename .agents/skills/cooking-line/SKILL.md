# 做菜线（cookline）

先读[插件 README](../../../08_作品/_共享工具/cookline/README.md)的「四、菜谱卡」「五、五条命令」「六、29 条拦截」。读[翻车登记表](../../../08_作品/_共享工具/cookline/rules/failures.json)定位具体编号；需要格式依据时读[秃秃拉片](../../../08_作品/小蛋仔做菜/00_方案/01-参考拉片-蘑菇做饭日常.md)与[16 拍设计](../../../08_作品/心易做菜/00_方案/04-参考工作流设计挖掘-v1.md)。

## 什么时候用

- 要做一条新的做菜短片：先定菜、定角色、定台地，再写菜谱卡。
- 已有菜谱卡要出画布：校验 → build → 过闸门。
- 出片后返修：先用 `doctor` 看是不是手改，再改卡重建。
- 旧卡（小蛋仔 `build_from_recipe` 或心易 `build_from_slope`）：先 `migrate` 做兼容审计，不直接 build。

## 流程

1. **定范围**：菜、角色、四个台地、16 拍还是 12 拍。创作决定归用户；插件只给格式与拦截。
2. **写卡**：`run.py new` 起骨架；每拍写 `start/do/end`，把 `props/hand/counts/state` 账本填上。道具后面要用，第一拍就得在画面里，或由 `enter` 带进来。
3. **校验**：`run.py check <卡> --strict`；ERROR 必须清零，WARN 要么改卡要么说明为什么保留。
4. **出画布**：`run.py build <卡> -o <x.monet>`；同时得到 runlist、边车、SRT。**不导入、不派发。**
5. **过闸门**：`assets → storyboard → keys → videos`，每道 `gate approve` 必须写看到了什么；`runlist` 只放行，用户明确说「跑」才派发。
6. **出片后**：`doctor` 查画布；按 F01–F29 逐条过，新翻车补进 `rules/failures.json` 并加一条反例测试。

## 硬规矩

- **卡是唯一内容源**：提示词、字幕、节点都从卡生成；不手改 `.monet`，改了会被 digest 抓住。
- **字幕只进 SRT**：提示词里只写「不生成任何字幕」，不写具体文案。
- **一段一个台地**：要换景就拆两条；段间只带得走的东西，用 `carry` 声明。
- **旧卡不硬跑**：`migrate` 只做审计；补不齐 `props/hand/state` 就不 build。
- **校验通过 ≠ 好看**：表演、节奏、治愈感留给人，不写成通过。
- **不越权**：不生成、不导入、不删除、不发布；付费与派发每次都要用户明确授权。

## 产物

`<卡>.monet`、`<卡>.monet.runlist.json`、`<卡>.monet.cookline.json`、`<卡>.srt`、`<卡>.gates.json`；说明具体改了哪张卡、过了哪道闸门、还有哪些 HUMAN 未判定。
