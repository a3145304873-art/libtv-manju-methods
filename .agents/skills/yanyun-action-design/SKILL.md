# 燕云双页面动作设计

## 必须读取与任务分类

先读根目录 `AGENTS.md`（若当前会话尚未加载）、[燕云项目入口](../../../08_作品/燕云冲击帧/README.md)和[双页面方案/参考包](../../../08_作品/燕云冲击帧/00_方案/32-双页面设计与外部参考包-候选.md)。将任务标成 A 冲击帧角色高光、B 恢弘大招，或 A+B。已有明确产物时接入对应阶段，不重跑无关流程。

- B 大招涉及剑气、剑阵、冰龙、法相或环境奇观时，加载 `industry-xuanhuan-combat/SKILL.md`，按需查 C18/R02/I07。它负责力量来源、武器映射、奇观尺度与特效层次。
- 需要拉片、逐帧借鉴或改写指定视频时，加载 `reference-video-adaptation/SKILL.md` 与 I03；只使用已提供或本轮确实可访问的媒体。标明未播放、未找到或未核对的来源。
- 需要搭建/改动 `.monet` 时，另加载 I06 与 C16。方案撰写本身不代表获准导入、运行或派发。
- 动作、运镜、角色设定图各自承担不同参考职责；除非用户明确指定，不让角色静态图替代动作参考，也不让动作片决定角色身份或运镜。

## 设计顺序

1. 锁定角色身份、A1/A2 角色锚点、A5 武器锚点，以及本任务已确认的画幅、风格和时长。未确认的信息列为假设或待定，不自行写成既定设定。
2. 先写身体与武器动作，再写特效。至少写清起势、支点/重心、躯干带动、手臂与握剑、剑锋起点、路径、目标/落点、受力反馈、制动和收势。每一拍的终态要能接下一拍。
3. 单独规划镜头路线和角色/剑路线；每个镜头有明确的阅读职责。避免同一拍同时安排多种相反运镜，避免特效遮住脸、手、剑路或命中点。
4. 大招的主奇观必须依附动作因果：角色出手 → 力量沿剑势/载体移动 → 命中或改变环境 → 余波/消散。选择一个主奇观形态；用人物、目标、地形或建筑作尺度参照。
5. 冲击帧从完整动作中选定格：起势 → 可见发力 → 冲击点 → 制动定格。定格必须仍读得出是谁在发力、剑往哪走；闪白、墨凝、冰裂等只设一个主爆点。

## 产前门槛

准备交付可直接生成的提示词、分镜或画布前，逐项核对。未通过的项目不得标记为“定稿/可生成”；可以先交候选稿，并将缺项写在对应项目下。

### A｜冲击帧角色高光

- 定格前有可见动作来源，而非只换姿势或背景。
- 起势、运动方向、剑锋路线、冲击点、制动定格能在关键帧/分格中读清。
- 关键挥斩格优先让剑身宽侧面处于画面平面内，避免无意的朝镜头透视把剑路压成一点；只有明确设计为刺击时才使用剑尖朝镜头。
- 脸、持剑手、剑形和剑路有足够辨认信息；墨/光效不盖住关键轮廓。
- 角色与武器身份跨帧稳定；参考图、动作参考、运镜参考各司其职。

### B｜恢弘大招

- 已有角色/武器路线图和单独的相机路线；剪影下动作也成立。
- 支点、重心、躯干发力、剑锋起点—路径—落点、目标反应、制动/收势可追踪。
- 主奇观有来源、载体、路径、命中/场景反馈和余波；有可读尺度锚点。
- 一拍一主动作，接触与反作用可见；特效不能代替角色动作或让目标落点含糊。
- 释放格必须看清完整身体发力与剑路；命中/收势格同时保留可辨认的角色制动和环境结果。纯远景若角色缩成不可辨认的小点，不能单独承担动作或结果镜头；应在读清动作后再揭示更大尺度。

两页都要核对提示词未引入未确认剧情、角色设定、固定时长或模型专属参数。时长按动作节拍分配，不平均切分。

## 返修与证据状态

输出后按首要故障分类为：身体/动作、镜头可读性、角色/武器一致性、特效因果/尺度。每轮优先改一类变量，并记录源版本、修改项和观察结果；没有实际输出时不得声称验证有效。

参考状态分别写 `候选`、`已确认`、`已观看/拆解`；画布状态分别写 `已搭建`、`已导入`、`已运行`、`已验收`。文件存在、搜索摘要、画布结构校验都不能替代实际观看或成片验收。

推荐交付字段：页面/阶段、参考及状态、角色动作链、剑路、相机路线、逐拍分镜与特效因果、产前门槛结果、假设/缺口、下一步。门槛不通过时明确标 `候选，未过产前门槛`，并指出缺哪项。
