# 新工作流与 Skill 的统一接入

## 接入顺序

1. 保存原始来源、接收日期、作者/平台、稳定 ID、版本、原文和哈希。仅链接且无法访问时登记待补，不宣称已读。
2. 核对重复：同稳定 ID 是版本更新；相同文件哈希保留来源指针；同名跨平台不自动合并；同系列不同集数可独立成例。
3. 拆实际结构：提示词在哪、真实媒体/文本输入、顺序、模型/模式、输出、候选和后期关系。教程的作者主张与节点快照事实分开。
4. 为每个适用阶段写触发问题、学习点、最低阅读包、前置条件、排除情形、产物与停止条件。
5. 先补已有能力卡证据或创建有条件分支，确有新机制才增加 ID。查看[规范能力索引](../01_能力库/能力卡.md)再分配编号。
6. 记录缺失依赖、未看媒体、未知采用版和待验证项。不补造不存在的原文、工具或结果。
7. 更新来源清单、案例或行业索引、能力卡和阶段路由；刷新盘点并运行检查。

资料入库可直接执行。新来源不能自动替换当前任务的已确认参考，使用前仍在相应制作阶段确认。

## 文件安排

- 原始文件：`04_原始资料/<workflows、industry-skills 或 format-references>/<ID>/<版本>/`，首次可以使用既有的根版本布局；保留原件不覆盖。仅提取格式的来源可保存指纹与结构元数据，明确原正文未导入。
- 工作流接入：`02_案例库/<ID>-短名称.md`。
- 技能工艺：`03_行业Skill/<ID>-短名称.md`。平台函数与历史配置保留在来源层，适配入口只写当前可执行工艺。
- 格式参考：`07_格式参考/<Rxx>-短名称.md`；去题材化的结构模板放 `05_模板`。用户仅要求格式与逻辑时，保留来源指纹和结构证据，不默认复制具体故事正文。
- 元数据：在 `source-manifest.json` 的 `sources` 追加该来源与文件，记录独立证据状态。每个文件至少有 source_relative、path 和 sha256。

现有复制原文使用 `.md.txt` 保存完整文本，避免历史相对链接被误认为本库导航；正常阅读从案例或工艺卡进入。保留原来的 Markdown 内容和全部提示词字节。

## 不同来源的证据边界

| 输入 | 可整理内容 | 保留缺口 |
|---|---|---|
| 节点快照 | 参数、真实输入、输出记录、依赖 | 未观看、采用版、历史配置缺失 |
| 技能/教程 | 作者步骤、提示词和使用条件 | 工具可用性、隐藏输入、运行结果 |
| 成片 | 时间码、可见镜头、动作、声音与节奏 | 原始提示词和实际生成编排 |
| 链接 | 可访问到的内容 | 无法访问的正文、素材和附件 |

新格式先保留原件再解释；当前[刷新盘点工具](../06_工具/刷新盘点.py)仅解析已有兼容 LibTV 快照。未知格式须新增并验证解析器，不能强套字段。

## 接入记录

使用[新来源模板](../05_模板/新来源接入.md)，至少填写阶段映射、来源定位、缺口、已有能力关联与下一次最小验证问题。接入后反馈“新增了什么、何时学什么、目前读/看到哪、有什么缺口”，无需先展开整库。
