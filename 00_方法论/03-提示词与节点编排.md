# 提示词与真实输入

## 1. 分开保存三种内容

- 原文：来源、版本、节点 ID/小节和字段定位。
- 方法解释：解决的问题、变量、前置条件和研究推断。
- 本次执行版本：用户确认范围内的提示词、媒体绑定、规则版本与实际参数。

公共规则维护在一处，提交时按需要展开为完整节点文本并记录版本。修改原例拼写或矛盾应形成新版本，不悄悄更改来源。

## 2. 提示词模块

| 模块 | 要说明的内容 |
|---|---|
| 段落任务 | 让观众看懂或感受到什么变化 |
| 输入绑定 | 哪个主体/场景/物件/声音来自哪个实际输入，引用顺序是什么 |
| 风格证据 | 可观察的材质、色彩、光线、构图与表演，而非只堆品质词 |
| 空间与动作 | 人物定位、视线、接触点、触发/起点/终点/重量及结果 |
| 摄影与节奏 | 景别、机位、运动理由、切镜规则、反应与停顿 |
| 声音 | 台词、说话人、口型、环境声、动作声、音乐用途与留白 |
| 段落边界 | 起止姿态、持物与装备状态、下一段要接住的动作 |
| 局部限制 | 当前高风险错误，如多余主体、换手、串声或重复动作 |

大招/必杀技段另按 [R02 五拍与五层特效栈](../07_格式参考/R02-大招演出提示词格式.md)（C18）展开：蓄势→展开→释放→碰撞→收势；一拍只主推一层特效，其余层做响应，收势必须有可见结果。不要把五层同时堆进同一拍。

## 3. 两种文本承载方式

**文本输入型**：分镜作为真实文本列表输入，视频 prompt 负责执行与局部约束。W05 提供这种参数证据。读取时把 `textList` 内容一起看。

**内嵌分镜型**：将必要公共规则与本段镜头写进视频 prompt，另外实际传入媒体。W04/W07/W09 提供此类样本。

按当前工具支持选择。不能把原文里的 `generate_video_v3` 等平台内部函数当成本机已有 API。长短提示词都要按实际输入完整性和输出效果判断。

## 4. 节点与依赖

逻辑节点类型：目标/脚本 → 必要资产 → 分段生成 → 选择或返修 → 剪辑/声音 → 验收。音色、演唱、强接续、状态图、增强等节点按需求加入。

每个执行节点记录：用途、输入节点/文件/版本/角色、完整提交文本、模型原始标签、模式、请求参数、输出元数据、依赖、候选 ID、状态与错误。使用[镜头与节点模板](../05_模板/镜头与节点.json)。

分别维护素材依赖图、故事顺序与剪辑采用表。画布坐标和“副本”命名不能替代其中任何一个。

## 5. 声音与编辑分支

音频输入要说明是音色参考、对白时间基准、演唱切片、节奏参考或最终配乐。锁音色不等于锁口型和台词时序；启用声音不等于传入独立音频。

局部重拍记录源视频版本、编辑区间、保留项、修改项和补充锚图。W09 的 `segmentRemakeDraft.ranges` 是源片编辑范围；`duration=0` 是其编辑配置，不能当成零秒输出，更不能推广到其他平台。

当下执行前读取对应 CLI 实际帮助和模型 schema，核对支持的媒体、模式、时长、数量和声音开关；历史快照仅说明当时保存的参数。

## 6. LibTV 接口适配边界

本库只包装工艺与记录，不附可执行文件、登录凭据或私有接口。目标环境有官方 `libtv` 时，通过其帮助核对 `project`/`node` 查询与生成用法；明确传目标画布，避免改动不相关上下文。

只读采集与生成分别授权；严禁为整理资料触发 `--run`。实际生成按官方 CLI 的同步终态约定执行并核验结果。模型任务成功、文件存在、用户选择参考与视觉验收分别记录。

## 7. 画布执行载体（已采用：Monet）

2026-10-29 起，画布搭建统一按 [I06 Monet 画布搭建方法](../03_行业Skill/I06-Monet画布搭建.md)执行（.monet 纯 JSON，用户确认的核心搭建格式）：接线数据只在 build 脚本一处定义、edges 由 `reference_images`/`first_frame` 派生生成；引用双接入（prompt token 与数据字段、图上边同时成立才生效）；组＝依赖分层＝跑序，组内无依赖边；交付前必跑工作区校验脚本。

LibTV 案例（W01–W10）的节点 JSON 证据用于提炼工艺原则，字段与结构不直接照搬；上节 LibTV 接口边界只适用于对 LibTV 来源的采集与复现。画布坐标和分组是编排载体，不替代[漫剧生产流程](../00_方法论/02-漫剧生产流程.md)的四级记录。
