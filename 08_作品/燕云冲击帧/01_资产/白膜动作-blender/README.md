## 幅度是怎么做大的（2026-11-02 按用户反馈重做）

第一版动作"看着不够有劲"，逐条比对参考片（`Downloads/冲击帧3.mp4` 拔剑段、`冲击帧2.mp4`）后定位到四个原因，本版全部改掉：

1. **剑太小** → 刃长 0.92m 改 **1.30m**（参考片里刃明显超过腿长，是"巨刃"）。刃长度直接决定斜线的气势。
2. **站姿并腿** → 改 **宽站姿 + 屈膝压低**：两腿外展 20–26°、膝盖弯 14–32°，下沉量按几何算 `0.85·(1−cos crouch·cos spread)`，保证脚不悬空。
3. **动作走错了方向** → 这是最关键的一条。相机是固定的正面机位，**朝镜头（fwd）方向的位移在画面上几乎看不见**（透视缩短）。第一版爆点大量用"上身前压、手臂前伸"，所以在画面里读不出幅度。本版把主幅度改走 **`side`（画面平面内的俯仰弧）**：01 手臂走 200° 过顶弧、03 elevation 从 +126° 扫到 −80°（全弧 206°）。
4. **爆点手臂缩回躯干里** → 手臂只有 0.62m，落到体侧时整条臂被躯干剪影吞掉。本版爆点定在"手伸到剪影之外"的位置（01 手横伸到 x≈−0.6 与肩平；02 双手宽于肩 ±52°），并在爆点后加 **4–5 帧过冲**（冲过目标姿势再 settle），动作才有回弹的力。

另加：躯干侧压 + 拧转、腰胯 yaw 摆幅（03 达 60°）、重心前后上下（`root_shift` 前后 0.2m / 下沉 0.22m）、收势段轻微呼吸。

## 复现 / 改动作

1. 环境：Blender 5.2.3 LTS，本机解包在 `C:\Users\N31738\AppData\Local\Programs\BlenderExtract\Blender Foundation\Blender 5.2\blender.exe`（winget MSI 装不上要管理员，用 `msiexec /a` 免提权解包）。
2. 三种运行模式（都在 `build_mocap.py` 里）：
   - 全量渲染：`blender --background --factory-startup --python build_mocap.py`
   - 关键姿势预览（半分辨率 7 帧/条，不占全量时间）：加环境变量 `MOCAP_PREVIEW=1`
   - 只跑审计不渲染：`MOCAP_AUDIT=1`；再想看剑尖轨迹加 `MOCAP_TIPS=1`
3. 合成 MP4：`bash make_mp4.sh`（本机 ffmpeg，24fps CRF18）。
4. 改动作：用 `K(关节, 帧, fwd=, side=, twist=)` 语义角标关键帧——`side` 正=画面右/抬举，`fwd` 正=朝镜头，`twist`=绕段轴。`stance(帧, crouch, spread, dy, yaw)` 一次设好宽站姿与重心。轴向有疑问时先跑 `cal_axes.py` 标定。

## 技术备忘（踩过的坑）

- **`fwd` 在正面机位几乎不可见**（见上文第 3 条）——设计幅度优先用 `side`。
- **刃的朝向 ≈ 肩角 + 肘角**。两角各自线性插值时，其和可能穿过 0（= 刃竖指地面），1.3m 的刃会插进地里。解法：把肘角**连续展开**（例如 04 的肘从 −136° 一路到 −360°，视觉上就是直臂），让两角之和单调经过"正上方"。03 用另一招：中段折肘把刃收短越过正下方。
- 本机 5.2 提取版 `image_settings.file_format='FFMPEG'` 赋值被动态枚举拒绝 → 出 PNG 序列 + 外部 ffmpeg 合成。
- 骨骼 BONE_RELATIVE 父级的 `matrix_parent_inverse` 约定在 5.2 上不可靠 → **改用空物体 FK 关节链**。要点：挂父级**之前**先存 `child.matrix_world`（该属性在挂父级瞬间被重算），`inv = parent.mw⁻¹ @ child.mw @ basis⁻¹`。
- 关键帧 `location` 会整体替换创建位置（root 的 1.02m 高度要加回去）；Workbench 阴影属性是复数 `show_shadows`。
