## 零、一句话

**只做英语故事画布的"内容设计—结构生产—门禁"这一段：人给一个词，模型只写 `story.json`，代码负责 prompt、接线、字幕、卡尾与全部踩坑检查，最后一键出 `.monet`。**

## 一、为什么 v1 不够：三个判断

v1 的方向没错（DSH Skill + CLI + 模板），但它把三件事混在一起，导致"通用"= 每条规则都能被另一条规则反驳：

| v1 的写法 | 实际问题 | v2 的改法 |
| --- | --- | --- |
| 一个插件同时管"谐音故事"和"词族故事" | 两套结构（15s 单段 / 23s 三段）的规则互相打架：23s 要求"黄蛋说出单词"，15s 定稿里词只在卡尾；23s 要 T_A/T_B，15s 明确"不用 T_A、不用 V2" | **profile 分流**：结构、时长、镜数、卡数、旁白、是否需要尾帧全部由 profile 声明，规则按 profile 生效 |
| 让模型直接写 `.monet` 或让模型"照着文档写 prompt" | 模型会漂：漏 token、负向泛化、道具凭空出现、时长不整 | **创意与硬约束分离**：模型只产出 `story.json`；prompt/接线/字幕/卡面由代码从同一份数据派生 |
| 把踩坑写在文档里，靠人记 | 人记不住 40 多条；改稿时总在同一个坑里摔第二次 | **规则即代码**：61 条规则带 ID/级别/修复/出处，报告直接给"哪条、为什么、怎么改" |

结论：**垂直不是"功能更少"，而是"每条规则只在一个 profile 里成立，并且由代码执行"。**

## 二、边界

**做：**

- 输入：一个英语词（或词族词根）＋中文谐音＋中文词义（＋可选场景偏好）；
- 产出：`story.json` 校验 → `.monet` ＋ `.srt` ＋ 校验报告；
- 复用：角色（黄蛋/心易）、眼睛锁、场景、道具图的既有 URL（`assets.json`）。

**不做（明确留给人/别的环节）：**

- 不生成图片/视频、不导入 Monet、不删除、不派发（仍要每次明确授权）；
- 不选角、不换画风、不加第三个角色、不做中文漫剧；
- 不把 `out/` 当资产库；要复用的图先登记进 `assets.json`；
- 不做"画布内一步成片"（Monet 文本节点→视频 prompt 尚未验证，W11 是 LibTV 智能体，不是 Monet）。

## 三、架构：三层，每层只有一个事实源

```
brief（任务书）        story.json（人/模型写）        .monet（代码生成）
   ↑ 硬规则、模板          ↑ 唯一创意载体              ↑ prompt/接线/字幕/卡
   └────────────── 同一份 rules.py ──────────────────┘
```

1. **brief**：`cli.py brief` 从 profile + rules 生成任务书，把"什么算过"提前告诉模型，减少返工；
2. **story.json**：唯一的创意输入。字段见 §四；不含任何节点 ID、坐标、token；
3. **builder**：从 story + profile + assets 生成节点/边/组，prompt 由 `prompts.py` 统一拼装；
4. **checks**：G（故事）/ P（prompt）/ C（画布）/ A（资产）四层，任一层 ERROR 即阻断。

单一事实源的意义：改一句台词只改 story；改角色锁只改 `prompts.py`；改规则只改 `rules.py`；**不在三个地方各写一遍**——这正是以前 `build-*.py` 越堆越多的原因（`02_画布/` 现有 30+ 个 build 脚本）。

## 四、数据契约（story.json）

```json
{
  "schema": 1,
  "id": "pest-15s",
  "profile": "harmonic15",
  "status": "locked",
  "word":     {"spelling": "pest", "ipa": "/pest/", "zh": "拍死它", "meaning": "害虫"},
  "hook":     {"line": "第二十一下——拍死它！", "who_says": "黄蛋",
               "why_natural": "谁在什么场景真会说", "meaning_link": "object",
               "why_meaning": "字面怎么落到词义"},
  "scene":    {"name": "夏夜小院石桌", "why": "为什么这个场景让字面动作成立", "asset": "A02"},
  "props":    [{"name": "苍蝇拍", "form": "形状/不是什么", "first_frame": true, "at": "0.0s 在哪"}],
  "trigger":  {"name": "卡通小蚊", "form": "…", "at": "…", "note": "不算道具"},
  "beats":    [{"start": 0, "end": 3, "shot": "中景", "action": "…", "speaker": "黄蛋",
                "line": "…", "sfx": "…"}],
  "card":     {"word": "pest", "zh": "拍死它", "meaning": "害虫"},
  "subtitles":[{"start": 0.8, "end": 2.0, "text": "第二十一下——"}],
  "scores":   {"natural": 24, "meaning": 25, "visual": 22, "character": 24},
  "continuity": {"no_rescue": true, "no_spoiler_next": true,
                 "scene_state": ["0.0s 已经就位的状态"], "hands": "两只短手"},
  "negatives": ["这条故事特有的负向"],
  "assets_why": {"A05": "新道具图", "K_A": "新首帧", "KC": "新卡"}
}
```

四条约定：

- `speaker` 可以写"黄蛋/心易/旁白"，载入时统一成 `huangdan/xinyi/narrator`；
- `hook` 必须给**证据**（为什么自然、义怎么接），不是形容词；
- `beats` 只写画面与台词，不写"镜头怎么运"以外的技术参数；
- 视频参数（模型、分辨率、画幅、时长）只在 profile，不在 story。

## 六、本次实现新抓到的两个坑

1. **道具图不能带词。** A05 的第一版 prompt 写了"目标词：pest（谐音：拍死它）"，模型很可能把 `pest` 烧进白底道具图——负向写"无文字"也挡不住正向给词。已改为道具图只写形状与"不是什么"，并新增 P13。
2. **锁眼句和"只拍爪"的特写会自相矛盾。** 原句"眼睛全程睁开、白色圆形眼片完整可见"，遇到 9–11s 只拍心易前爪与桌面的特写时，模型会被迫把脸塞进画面。已改为"**眼睛入画时**全程睁开、完整可见"，并在该拍写明"心易的脸不入画"。

这两条都不在旧文档里，是"先写代码再写规则"跑出来的——也说明门禁必须跑真实样例，不能只写文档。

### 六点五、分镜图闸门（2026-11-03 新规范，已落地）

AGENTS.md 当天下发：**每段视频生成前先出三格分镜图（0/5/10s），第一格必须含本段全部道具与人物站位，确认后再跑视频。**

插件的落法：

- profile 里 `storyboard: true` → builder 自动生成 `G1` 节点（gen-image，横向三等分 0/5/10s）；
- G1 的参考＝角色＋场景＋道具图；**G1 不接视频**（多宫格会干扰构图，I06 的派生参考只到关键帧）；
- 跑序变成：`A05 道具图 → G1 三格分镜（人工确认）→ K_A 首帧（构图对齐第一格）→ V1 → KC`；
- 门禁：**C20**（没有分镜图节点就 ERROR）、**P14**（第一格没点名全部道具或站位就 ERROR）。

pest 的 G1 直接取 0s / 5s / 10s 三拍的动作，第一格写明"苍蝇拍在桌右、水果盘在桌中、卡通小蚊在盘沿、两人站位在这一格定死"。

- 包名 `@local/english-story`，源码在 [`../../../.plugins/english-story/`](../../../.plugins/english-story/index.js)（package.json ＋ cordis.patch.yml ＋ index.js ＋ locale ＋ icon）；
- 安装命令 `plugin_manager install_bundle target="E:\libtv漫剧\.plugins\english-story"`，返回 `application: applied`；
- 注册 4 个工具：`english_story_brief` / `english_story_validate` / `english_story_build` / `english_story_check`；
- 工具只是 CLI 的薄壳：`ctx.subprocess.spawn` 跑 `py -3 cli.py …`，逻辑不重复，CLI 仍是唯一事实源；
- 配置项：`workspace`（CLI 目录）、`python`（`C:\Windows\py.exe`，系统 `python` 是 2.7，必须显式 `-3`）；
- 插件不联网、不碰 Monet、不生成素材；卸载用 `plugin_manager remove_bundle target="@local/english-story"`。

**创作模式（preset）**：另装 `@local/dsh-english-story-preset`，roster 里叫「英语故事画布」，把流程钉成 S0 选题 → S1 想 3 版 → S2 人选 → S3 验证 → S4 建画布 → S5 复检 → S6 交付，每阶段一个停点。preset 只对新会话生效；当前已开会话保持原模式。

选 preset 而不是 workflow 工具的理由：workflow 是并发跑完、人插不进“选稿”，而这条件恰恰要求在 S2 停、S3/S5 各设一道门——以前“跳过验收直接建画布”的问题只能靠停点挡。

验证：4 个工具各调通一次（build 出 11/17/7），中文输出正常；未验证 Plugin Manager 里的标题/描述/图标渲染（无浏览器控制）。
